title: "Password-Protecting Collections and Documents in Whisker"

Password protection is the simplest way to restrict access to a collection or document in Whisker. Anyone who has the password can view the resource — no Whisker account required. This makes it a great option for sharing research with external reviewers, clients, or collaborators who don't need a permanent seat in your workspace.

## Setting a Password

You can enable password protection directly from the Whisker UI in a few steps.

<Steps>
  <Step title="Open the collection or document">
    Navigate to the collection or document you want to protect.
  </Step>
  <Step title="Open Settings">
    Click the **lock icon** in the top-right toolbar, or go to **Settings** from the item's action menu.
  </Step>
  <Step title="Enable password protection">
    Toggle on **Password Protection** and enter the password you want to use.
  </Step>
  <Step title="Save">
    Click **Save**. From now on, any visitor who navigates to this resource will be prompted to enter the password before viewing it.
  </Step>
</Steps>

## Password Requirements

Whisker enforces a minimum password length of **8 characters**. There are no additional character-type requirements, so you can choose whatever format works best for your use case.

## Via the API

You can also enable or update password protection programmatically using the permissions endpoint.

**Check current password protection status:**

```http
GET /api/v1/permissions/col_abc123
Authorization: Bearer YOUR_API_KEY
```

```json
{
  "resource_id": "col_abc123",
  "password_protected": false,
  "members": []
}
```

**Enable password protection:**

```http
PUT /api/v1/permissions/col_abc123
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "password_protected": true,
  "password": "my-secure-password"
}
```

```json
{
  "resource_id": "col_abc123",
  "password_protected": true
}
```

Replace `col_abc123` with the ID of your collection or document. For documents, use the document ID (e.g., `doc_abc123`).

## Changing or Removing a Password

To change an existing password, follow the same steps as setting one — enter a new password in the **Password Protection** settings and save. The old password is immediately invalidated.

To remove password protection entirely, return to **Settings**, toggle off **Password Protection**, and save. The resource becomes accessible without any password prompt.

Via the API, set `"password_protected": false` in the same `PUT /api/v1/permissions/{resource_id}` request to remove the password gate.

## Password + Role Access

Password protection and role-based access work independently but complement each other. If a resource has both a password and role-based permissions configured, **role members bypass the password prompt entirely** — they authenticate through their Whisker account instead.

This means you can lock down a document with a password for external visitors while your internal team members (assigned as Editors or Viewers) access it seamlessly without entering anything.

<Warning>
  Whisker does not store passwords in a recoverable form. If you lose the
  password for a protected resource, only a workspace admin can remove the
  password protection via the API or admin settings. Make sure to store
  passwords somewhere safe.
</Warning>

## AI Agent Access with Passwords

AI agents do not enter passwords manually. Instead, you grant an agent access to a password-protected resource by issuing an **agent token** and explicitly scoping that token to the collection or document. Once the token is scoped, the agent can access the resource without needing the password. See [Connecting Agents](/agents/connecting-agents) for details on how to create and scope tokens.
