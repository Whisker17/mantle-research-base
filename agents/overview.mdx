Whisker is designed from the ground up to serve as a knowledge source for AI agents. This means your research, reports, and notes are structured and accessible programmatically, so agents like ChatGPT, Claude, and custom LLM-based tools can query and read them — without any manual copying or reformatting on your part.

## How Agent Access Works

Every agent interaction follows the same three-step flow:

<Steps>
  <Step title="Create an Agent Token">
    Generate a scoped token in your Whisker settings. You choose exactly which collections the token can access and whether it has read-only or read-and-write permissions.
  </Step>
  <Step title="Agent Authenticates with the Token">
    Your AI assistant or LLM pipeline includes the agent token in the `Authorization` header of each API request.
  </Step>
  <Step title="Whisker Returns Authorized Content">
    Whisker checks the token's permissions and returns only the documents and collections the token is allowed to see — nothing more.
  </Step>
</Steps>

## What Agents Can Do

Agent tokens give AI assistants direct, structured access to your knowledge base. By default, an agent with read access can:

- **List collections** they are authorized to access
- **Read document content** returned as plain text or Markdown, ready for LLM consumption
- **Search across authorized documents** using keyword or semantic queries
- **Retrieve document metadata** such as titles, formats, and last-updated timestamps

<Info>
  Agent tokens are separate from your personal user API keys. They are purpose-built for non-human callers and follow the principle of least privilege — each token only accesses what you explicitly allow. Agents **cannot** create, edit, or delete content unless you explicitly grant write access when creating the token.
</Info>

## Agent Token vs. User API Key

Understanding the difference helps you choose the right credential for each use case.

| | **Agent Token** | **User API Key** |
|---|---|---|
| **Intended for** | AI assistants and LLM pipelines | Developers and personal integrations |
| **Scope** | Limited to selected collections | Full account access |
| **Default permissions** | Read-only | Read and write |
| **Prefix** | `AGT_` | `USK_` |
| **Revocable per agent** | Yes — each token is independent | Single key per user |
| **Audit trail** | Logged separately from user activity | Logged as user activity |

Use agent tokens whenever you are connecting a third-party AI tool or an automated pipeline. Reserve your user API key for scripts and integrations that you personally own and operate.
