Agents interact with Whisker entirely through the REST API, using their agent token to authenticate each request. Every response is structured JSON, and all document content is returned as plain text or Markdown — ready to be fed directly into an LLM prompt without any preprocessing.

## Listing Accessible Collections

To see which collections your agent token has access to, call the collections endpoint. This is a good first step for agents that need to discover available resources dynamically.

```http
GET /api/v1/collections
Authorization: Bearer AGT_your_agent_token
```

**Response:**

```json
{
  "collections": [
    {
      "id": "col_abc123",
      "name": "Market Research 2024",
      "document_count": 34,
      "updated_at": "2024-10-28T14:55:00Z"
    },
    {
      "id": "col_def456",
      "name": "Competitive Analysis",
      "document_count": 12,
      "updated_at": "2024-10-15T09:10:00Z"
    }
  ]
}
```

<ResponseField name="id" type="string">
  Unique identifier for the collection. Use this when listing documents or scoping a search.
</ResponseField>

<ResponseField name="name" type="string">
  Human-readable name of the collection.
</ResponseField>

<ResponseField name="document_count" type="integer">
  Total number of documents currently in the collection.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent change to the collection.
</ResponseField>

## Listing Documents in a Collection

Once you have a collection ID, you can list all documents inside it.

```http
GET /api/v1/collections/col_abc123/documents
Authorization: Bearer AGT_your_agent_token
```

**Response:**

```json
{
  "documents": [
    {
      "id": "doc_abc123",
      "title": "Q3 Consumer Sentiment Report",
      "format": "markdown",
      "size": 18432,
      "updated_at": "2024-10-20T11:30:00Z"
    },
    {
      "id": "doc_def456",
      "title": "APAC Market Entry Analysis",
      "format": "markdown",
      "size": 24100,
      "updated_at": "2024-09-05T08:00:00Z"
    }
  ]
}
```

<Tip>
  For large collections, use the `page` and `per_page` query parameters to paginate results. For example: `GET /api/v1/collections/col_abc123/documents?page=2&per_page=20`. The default page size is 20 documents per request.
</Tip>

## Reading a Document

To retrieve the full content of a document, request it by its ID.

```http
GET /api/v1/documents/doc_abc123
Authorization: Bearer AGT_your_agent_token
```

**Response:**

```json
{
  "id": "doc_abc123",
  "title": "Q3 Consumer Sentiment Report",
  "content": "## Executive Summary\n\nConsumer sentiment in Q3 showed a notable uptick across all tracked demographics...",
  "format": "markdown",
  "collection_id": "col_abc123",
  "created_at": "2024-07-10T09:00:00Z",
  "updated_at": "2024-10-20T11:30:00Z"
}
```

<ResponseField name="content" type="string">
  The full extracted text of the document, returned as plain text or Markdown. This field is ready for direct inclusion in an LLM prompt or context window.
</ResponseField>

<ResponseField name="format" type="string">
  The format of the `content` field — either `markdown` or `text`.
</ResponseField>

<ResponseField name="collection_id" type="string">
  The ID of the collection this document belongs to.
</ResponseField>

## Searching Documents

Use the search endpoint to find documents relevant to a query. You can search across all accessible collections or scope the search to a single collection.

```http
GET /api/v1/documents/search?q=market+analysis&collection_id=col_abc123
Authorization: Bearer AGT_your_agent_token
```

<ParamField query="q" type="string" required>
  The search query. Whisker supports both keyword and semantic (vector) search — the most relevant results are returned first.
</ParamField>

<ParamField query="collection_id" type="string">
  Restrict the search to a specific collection. Omit this parameter to search across all collections the token can access.
</ParamField>

**Response:**

```json
{
  "results": [
    {
      "id": "doc_abc123",
      "title": "APAC Market Entry Analysis",
      "relevance_score": 0.94,
      "excerpt": "...the APAC market analysis indicates strong growth potential in the mid-tier consumer segment, particularly in...",
      "collection_id": "col_abc123",
      "updated_at": "2024-09-05T08:00:00Z"
    },
    {
      "id": "doc_ghi789",
      "title": "Global Market Trends Overview",
      "relevance_score": 0.81,
      "excerpt": "...cross-market analysis reveals consistent demand patterns that align with the broader trends identified in...",
      "collection_id": "col_abc123",
      "updated_at": "2024-08-18T14:22:00Z"
    }
  ]
}
```

<ResponseField name="relevance_score" type="float">
  A score between 0 and 1 indicating how closely the document matches your query. Results are sorted highest to lowest.
</ResponseField>

<ResponseField name="excerpt" type="string">
  A short snippet of the most relevant passage in the document, useful for deciding whether to fetch the full content.
</ResponseField>

## Content Formats

All document content returned by the Whisker API is either **plain text** or **Markdown**. Whisker automatically extracts and normalizes text from uploaded files (PDFs, Word documents, and similar formats) so your agent always receives clean, LLM-ready content — no binary data, no HTML tags, no layout artifacts.

You can check the `format` field on any document response to see which format applies:

- `markdown` — content uses Markdown headings, lists, and emphasis, preserving document structure where possible
- `text` — content is plain prose, used when the source document has minimal formatting

Both formats are safe to inject directly into a prompt or pass to a retrieval-augmented generation (RAG) pipeline.

<Note>
  Agent tokens are subject to a rate limit of **60 requests per minute**. If you exceed this limit, the API returns a `429 Too Many Requests` response. Build exponential back-off into your agent's request logic to handle this gracefully. If your use case requires a higher limit, contact Whisker support to discuss an upgraded plan.
</Note>
