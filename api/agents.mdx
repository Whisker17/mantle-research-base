---
title: "Agent Tokens API: Create and Manage AI Access"
sidebarTitle: "Agent Tokens"
description: "REST API endpoints for creating and managing Whisker agent tokens — scoped credentials that allow AI agents to read authorized knowledge base content."
---

Agent tokens are scoped, non-human credentials designed specifically for AI agents. Unlike API keys, which carry the full permissions of the user who created them, agent tokens grant access only to the collections and operations you explicitly specify. This makes them well suited for read-only retrieval pipelines, RAG (retrieval-augmented generation) workflows, and any scenario where you want an AI agent to access knowledge base content without exposing broader account permissions.

---

## POST /agents/token

Create a new agent token. The token value is returned **once** in the response and cannot be retrieved again — store it immediately.

```http
POST /v1/agents/token
Authorization: Bearer wsk_live_your_api_key_here
Content-Type: application/json

{
  "name": "Research RAG Agent",
  "collection_ids": ["col_01hx9z", "col_03ab7y"],
  "access": "read",
  "expires_at": "2025-12-31T23:59:59Z"
}
```

**Body Parameters**

<ParamField body="name" type="string" required>
  A human-readable label for this token. Helps you identify it in the dashboard and in API responses.
</ParamField>

<ParamField body="collection_ids" type="array" required>
  An array of collection IDs that this token is authorized to access. The agent can only read documents from these collections.
</ParamField>

<ParamField body="access" type="string" default="read">
  The level of access to grant. Accepted values: `read`, `write`. Use `read` for agents that only retrieve content.
</ParamField>

<ParamField body="expires_at" type="string">
  Optional expiry date and time in ISO 8601 format. After this time the token is automatically revoked. Omit for a non-expiring token.
</ParamField>

**Response** — `201 Created`

```json
{
  "data": {
    "id": "agt_05xr1q",
    "name": "Research RAG Agent",
    "token": "AGT_v1.7kQpXz3mNwLsRtYdBcAeHjFuVoIgWnCk",
    "collection_ids": ["col_01hx9z", "col_03ab7y"],
    "access": "read",
    "created_at": "2024-11-11T11:00:00Z",
    "expires_at": "2025-12-31T23:59:59Z"
  }
}
```

<ResponseField name="data.id" type="string">
  Unique identifier for the agent token. Use this ID to list or revoke the token later.
</ResponseField>

<ResponseField name="data.name" type="string">
  The display name you provided for this token.
</ResponseField>

<ResponseField name="data.token" type="string">
  The full agent token value, prefixed with `AGT_`. **This is the only time this value is returned.** Copy and store it securely now.
</ResponseField>

<ResponseField name="data.collection_ids" type="array">
  The collection IDs this token has access to.
</ResponseField>

<ResponseField name="data.access" type="string">
  The access level granted: `read` or `write`.
</ResponseField>

<ResponseField name="data.created_at" type="string">
  ISO 8601 timestamp of when the token was created.
</ResponseField>

<ResponseField name="data.expires_at" type="string | null">
  ISO 8601 expiry timestamp, or `null` if the token does not expire.
</ResponseField>

<Warning>
  The `token` field is only included in the creation response. Whisker does not store the raw token value and cannot display it again. If you lose the token, revoke it and create a new one.
</Warning>

## GET /agents/tokens

List all agent tokens associated with your account. Token values are not included — only metadata.

```http
GET /v1/agents/tokens
Authorization: Bearer wsk_live_your_api_key_here
```

**Response**

```json
{
  "data": [
    {
      "id": "agt_05xr1q",
      "name": "Research RAG Agent",
      "collection_ids": ["col_01hx9z", "col_03ab7y"],
      "access": "read",
      "created_at": "2024-11-11T11:00:00Z",
      "expires_at": "2025-12-31T23:59:59Z",
      "last_used_at": "2024-11-12T09:14:33Z"
    },
    {
      "id": "agt_09bk7w",
      "name": "Internal QA Bot",
      "collection_ids": ["col_07qz4r"],
      "access": "read",
      "created_at": "2024-10-01T08:00:00Z",
      "expires_at": null,
      "last_used_at": "2024-11-11T17:52:10Z"
    }
  ],
  "meta": {
    "total": 2,
    "page": 1,
    "per_page": 20
  }
}
```

<ResponseField name="data" type="array">
  Array of agent token metadata objects. The raw `token` value is never included.

  <ResponseField name="id" type="string">
    Unique agent token ID.
  </ResponseField>

  <ResponseField name="name" type="string">
    Display name of the token.
  </ResponseField>

  <ResponseField name="collection_ids" type="array">
    Collections this token has access to.
  </ResponseField>

  <ResponseField name="access" type="string">
    Access level: `read` or `write`.
  </ResponseField>

  <ResponseField name="last_used_at" type="string | null">
    ISO 8601 timestamp of the most recent authenticated request made with this token, or `null` if it has never been used.
  </ResponseField>

  <ResponseField name="expires_at" type="string | null">
    ISO 8601 expiry timestamp, or `null` if the token does not expire.
  </ResponseField>
</ResponseField>

<Tip>
  Use `last_used_at` to audit token activity. Tokens that have never been used or haven't been used recently may be safe to revoke.
</Tip>

## DELETE /agents/tokens/{id}

Revoke an agent token immediately. Any request using this token after revocation will receive a `401 unauthorized` response.

```http
DELETE /v1/agents/tokens/agt_05xr1q
Authorization: Bearer wsk_live_your_api_key_here
```

**Path Parameters**

<ParamField path="id" type="string" required>
  The unique ID of the agent token to revoke.
</ParamField>

**Response** — `204 No Content`

An empty response body is returned on success.

<Note>
  Revocation is immediate and irreversible. If you need the same agent to keep working, create a new token and update the agent's configuration.
</Note>

## GET /agents/me

Allows an agent to identify itself and discover which collections it has access to. This endpoint is authenticated with the **agent token**, not an API key — it's designed to be called by the agent itself at startup or before making queries.

```http
GET /v1/agents/me
Authorization: Bearer AGT_v1.7kQpXz3mNwLsRtYdBcAeHjFuVoIgWnCk
```

**Response**

```json
{
  "data": {
    "token_id": "agt_05xr1q",
    "name": "Research RAG Agent",
    "access": "read",
    "collections": [
      {
        "id": "col_01hx9z",
        "name": "Research Reports",
        "access": "read"
      },
      {
        "id": "col_03ab7y",
        "name": "Q3 2024",
        "access": "read"
      }
    ]
  }
}
```

<ResponseField name="data.token_id" type="string">
  The unique ID of the agent token making this request.
</ResponseField>

<ResponseField name="data.name" type="string">
  The display name of the agent token.
</ResponseField>

<ResponseField name="data.access" type="string">
  The overall access level of this token: `read` or `write`.
</ResponseField>

<ResponseField name="data.collections" type="array">
  The collections this agent token can access.

  <ResponseField name="id" type="string">
    Collection ID.
  </ResponseField>

  <ResponseField name="name" type="string">
    Collection display name.
  </ResponseField>

  <ResponseField name="access" type="string">
    Access level for this specific collection: `read` or `write`.
  </ResponseField>
</ResponseField>

<Tip>
  Call `GET /agents/me` at agent startup to validate that the token is active and to dynamically discover which collections are available — rather than hardcoding collection IDs in your agent logic.
</Tip>
