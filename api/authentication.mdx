Every request to the Whisker API must be authenticated. Whisker supports two credential types: **API keys** for human and integration use, and **agent tokens** for AI agents. Both are passed as Bearer tokens in the `Authorization` header. No cookies, no sessions — authentication is stateless and explicit on every request.

## API Keys

API keys are the primary credential for humans and server-side integrations. You can generate and revoke API keys at any time from **Settings → API Keys** in the Whisker dashboard.

Authenticate by including your API key in the `Authorization` header:

```http
GET /v1/documents
Authorization: Bearer wsk_live_your_api_key_here
```

API keys inherit the full permissions of the user account that created them. Use test keys (prefixed `wsk_test_`) during development so you don't accidentally modify production data.

## Agent Tokens

Agent tokens are scoped, non-human credentials designed specifically for AI agents. They are prefixed with `AGT_` and can be restricted to specific collections and access levels. You can create agent tokens via the [Agents API](/api/agents) or from the Whisker dashboard under **Settings → Agent Tokens**.

```http
GET /v1/documents
Authorization: Bearer AGT_your_agent_token_here
```

Unlike API keys, agent tokens do not inherit account-wide permissions. They only grant access to the collections and operations explicitly configured at the time of creation.

<Note>
  Agent tokens are subject to a lower rate limit (60 req/min) compared to API keys (300 req/min). See the [Overview](/api/overview#rate-limits) for details.
</Note>

## Key Prefixes

Use the prefix to quickly identify what type of credential you're working with:

| Prefix | Type | Use Case |
|--------|------|----------|
| `wsk_live_` | API Key | Human and integration use in production |
| `wsk_test_` | Test API Key | Development and testing environments |
| `AGT_` | Agent Token | AI agent programmatic access |

## Common Auth Errors

**401 Unauthorized** — Returned when the `Authorization` header is missing, malformed, or the key has been revoked. Check that you're including the `Bearer ` prefix and that the key is active.

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Missing or invalid API key."
  }
}
```

**403 Forbidden** — Returned when the key is valid but does not have permission to access the requested resource. This commonly occurs when an agent token tries to access a collection it wasn't granted access to.

```json
{
  "error": {
    "code": "forbidden",
    "message": "You do not have permission to access this resource."
  }
}
```

<Warning>
  Never commit API keys or agent tokens to source control. Use environment variables or a secrets manager to inject credentials at runtime.
</Warning>

## Using Environment Variables

Store your credentials in environment variables and read them at runtime. Here's how to do that in Python and Node.js:

```python
import os
import requests

api_key = os.environ["WHISKER_API_KEY"]

response = requests.get(
    "https://api.whisker.app/v1/documents",
    headers={"Authorization": f"Bearer {api_key}"}
)

documents = response.json()
```

```javascript
const apiKey = process.env.WHISKER_API_KEY;

const response = await fetch("https://api.whisker.app/v1/documents", {
  headers: {
    Authorization: `Bearer ${apiKey}`,
  },
});

const documents = await response.json();
```

Set the environment variable in your shell or `.env` file (and make sure `.env` is in your `.gitignore`):

```bash
export WHISKER_API_KEY=wsk_live_your_api_key_here
```
