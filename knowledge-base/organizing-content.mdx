Collections are the primary organizational unit in Whisker. Every document lives inside a collection, and collections can be nested, shared, and access-controlled independently. A well-structured collection hierarchy makes it easy for both human researchers and AI agents to find the right content quickly — without sifting through an undifferentiated list of documents.

## Creating a Collection

You can create a collection from the UI or the API.

**In the UI:**

<Steps>
  <Step title="Go to your knowledge base">
    From the dashboard, select the knowledge base where you want to add a collection.
  </Step>
  <Step title="Click New Collection">
    Select **New Collection** from the sidebar or the main content area.
  </Step>
  <Step title="Name and describe it">
    Give the collection a clear, descriptive name and an optional description to help collaborators understand its purpose.
  </Step>
  <Step title="Set access level">
    Choose who can view or edit the collection: **Private**, **Team**, or **Public**. You can change this later in Collection Settings.
  </Step>
  <Step title="Save">
    Click **Create Collection**. The collection is now ready to receive documents.
  </Step>
</Steps>

**Via the API:**

```http
POST /api/v1/collections
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

```json
{
  "name": "Market Research 2024",
  "description": "Competitive analysis and market reports"
}
```

A successful request returns a `201 Created` response:

```json
{
  "id": "col_abc123",
  "name": "Market Research 2024",
  "description": "Competitive analysis and market reports",
  "created_at": "2024-10-01T08:00:00Z",
  "access_level": "private"
}
```

## Nesting and Hierarchy

Collections in Whisker support **sub-collections**, allowing you to build a multi-level hierarchy that mirrors the structure of your research program.

For example, a top-level collection called `Market Research 2024` might contain sub-collections like `Competitor Analysis`, `Customer Surveys`, and `Industry Reports`. Each sub-collection can hold its own documents and access controls, independently of the parent.

<Info>
  Sub-collections inherit the access level of their parent by default. You can override this in the sub-collection's settings to grant narrower or broader access for specific teams or agents.
</Info>

To create a sub-collection via the API, include a `parent_id` in your request:

```json
{
  "name": "Competitor Analysis",
  "description": "Direct and indirect competitor teardowns",
  "parent_id": "col_abc123"
}
```

## Moving Documents

You can move documents between collections at any time without losing their content, revision history, or metadata.

**In the UI:** Open the document, click the **⋯ More** menu, and select **Move to Collection**. Choose the destination collection from the picker and confirm.

**Via the API:** Update the document's `collection_id` with a `PATCH` request:

```http
PATCH /api/v1/documents/doc_xyz789
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

```json
{
  "collection_id": "col_def456"
}
```

<Warning>
  Moving a document changes the collection context for any AI agents that query by collection. If you have agents scoped to a specific `collection_id`, update their configuration after moving documents.
</Warning>

## Collection Settings

Each collection has its own settings panel where you can configure:

- **Access level** — `private` (only you), `team` (specific team members or API keys), or `public` (anyone with a link or API key)
- **Agent access** — toggle whether AI agents can read documents in this collection
- **Default document format** — set a preferred format (e.g., Markdown) for new documents created in this collection
- **Archiving** — archive a collection to make it read-only while preserving all its documents

Access the settings panel by clicking the **⚙ Settings** icon next to a collection name in the sidebar.

<Tip>
  For large knowledge bases, adopt a consistent naming convention early — for example, `[Year] [Topic] [Type]` (e.g., `2024 Competitors Analysis`). This makes collections predictable for both teammates and AI agents resolving queries by collection name.
</Tip>

## Listing Collections

Retrieve all collections your API key has access to using the `GET /api/v1/collections` endpoint:

```http
GET /api/v1/collections
Authorization: Bearer YOUR_API_KEY
```

```json
{
  "collections": [
    {
      "id": "col_abc123",
      "name": "Market Research 2024",
      "description": "Competitive analysis and market reports",
      "document_count": 14,
      "access_level": "team",
      "created_at": "2024-10-01T08:00:00Z"
    },
    {
      "id": "col_def456",
      "name": "Internal Strategy",
      "description": "Long-term planning documents",
      "document_count": 5,
      "access_level": "private",
      "created_at": "2024-09-15T11:20:00Z"
    }
  ],
  "total": 2
}
```

Use the `parent_id` query parameter to list only the sub-collections of a given collection:

```http
GET /api/v1/collections?parent_id=col_abc123
Authorization: Bearer YOUR_API_KEY
```
