Whisker makes it straightforward to bring existing research into your knowledge base — whether you're uploading a single PDF report or bulk-importing an entire archive of documents. Once uploaded, files are processed and indexed automatically, making their content available to both human readers and AI agents through a consistent interface.

## Drag-and-Drop Upload

The fastest way to upload files is directly from the Whisker UI.

<Steps>
  <Step title="Open a collection">
    Navigate to the collection where you want to store the uploaded files.
  </Step>
  <Step title="Drag your files">
    Drag one or more files from your desktop or file explorer and drop them anywhere inside the collection view. A blue highlight indicates a valid drop zone.
  </Step>
  <Step title="Set titles and metadata (optional)">
    Whisker auto-populates each document's title from the filename. You can edit titles and add tags before confirming the upload.
  </Step>
  <Step title="Confirm upload">
    Click **Upload** to start ingestion. Each file shows a progress indicator, and a status badge updates to **Ready** once processing is complete.
  </Step>
</Steps>

You can also click **Upload Files** in the collection toolbar to open a file picker if drag-and-drop is not available in your browser environment.

## Supported Formats

Whisker accepts the following file types for upload:

| Format     | Extension | AI-Readable |
|------------|-----------|-------------|
| PDF        | `.pdf`    | ✅ Yes       |
| Word       | `.docx`   | ✅ Yes       |
| Markdown   | `.md`     | ✅ Yes       |
| Plain Text | `.txt`    | ✅ Yes       |
| HTML       | `.html`   | ✅ Yes       |

<Info>
  All supported formats are indexed for AI agent access. For the best query performance, prefer Markdown or plain text when you have control over the source format.
</Info>

## Uploading via API

You can upload files programmatically using a `multipart/form-data` POST request. This is useful for automated report pipelines, nightly exports, or integrations with external research tools.

```http
POST /api/v1/documents/upload
Authorization: Bearer YOUR_API_KEY
Content-Type: multipart/form-data
```

```bash
curl -X POST https://api.whisker.ai/v1/documents/upload \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@/path/to/q4-competitive-analysis.pdf" \
  -F "collection_id=col_abc123" \
  -F "title=Q4 Competitive Analysis"
```

<ParamField body="file" type="binary" required>
  The file to upload, sent as a binary multipart field.
</ParamField>

<ParamField body="collection_id" type="string" required>
  The ID of the collection where the document should be stored.
</ParamField>

<ParamField body="title" type="string">
  A human-readable title for the document. Defaults to the original filename if omitted.
</ParamField>

<ParamField body="tags" type="array">
  Optional list of tags to apply to the document for filtering and discovery.
</ParamField>

A successful upload returns a `202 Accepted` response while the file is queued for processing:

```json
{
  "id": "doc_rpt001",
  "title": "Q4 Competitive Analysis",
  "collection_id": "col_abc123",
  "status": "processing",
  "created_at": "2024-10-22T10:15:00Z"
}
```

## File Size Limits

Whisker enforces the following limits to ensure platform performance and reliability:

| Limit                  | Value       |
|------------------------|-------------|
| Maximum file size      | 50 MB       |
| Maximum workspace size | 10 GB       |
| Files per upload batch | 25          |

<Warning>
  Uploads that exceed the 50 MB per-file limit will be rejected with a `413 Payload Too Large` error. If you need to upload large documents, consider splitting them into smaller sections or compressing embedded images before uploading.
</Warning>

## After Upload

When a file is uploaded, Whisker places it in a **processing** queue. During processing, the platform extracts text, detects structure, and builds the search index. Depending on file size and type, processing typically completes within a few seconds to a couple of minutes.

<Note>
  PDF text extraction depends on whether the PDF contains selectable text. Scanned PDFs without an embedded text layer will produce lower-quality extraction results, which can reduce AI agent readability. Whenever possible, upload PDFs exported directly from authoring tools rather than scanned images.
</Note>

You can poll the document's `status` field using the `GET /api/v1/documents/{id}` endpoint to check when it's ready:

```http
GET /api/v1/documents/doc_rpt001
Authorization: Bearer YOUR_API_KEY
```

```json
{
  "id": "doc_rpt001",
  "title": "Q4 Competitive Analysis",
  "status": "ready",
  "collection_id": "col_abc123",
  "created_at": "2024-10-22T10:15:00Z",
  "processed_at": "2024-10-22T10:15:34Z"
}
```

The `status` field will be one of the following values:

<ResponseField name="status" type="string">
  Current processing state of the document.

  - `processing` — the file is being ingested and indexed
  - `ready` — the document is fully processed and available to users and agents
  - `error` — processing failed; check the `error_message` field for details
</ResponseField>

If a document enters an `error` state, you can retry processing from the document's detail page in the UI, or re-upload the file via the API.
